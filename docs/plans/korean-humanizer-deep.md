# korean-humanizer-deep 설계와 검증

## 확정한 범위

`korean-humanizer-deep`는 관련 문맥을 조사해 한국어 글의 말투·구성·내용을 개선하는 별도 스킬이다. 기존 `korean-humanizer`는 의미·정보·말투 보존 교정을 담당한다. 원문 말투 변경과 근거 있는 내용 보충·오류 수정을 포함하므로 별도 호출로 구분한다.

원본은 `skills/korean-humanizer-deep/`다. 기존 스킬 설치 없이 독립적으로 사용하며, 카탈로그를 복제하거나 기존 스킬의 보존 교정 절차를 연쇄 호출하지 않는다. 이 문서는 설계 기록이며 실행 기준은 새 스킬의 `SKILL.md`가 정본이다.

## 사용

```text
$korean-humanizer-deep README.md
```

```text
$korean-humanizer-deep
아래 내용을 신규 입사자에게 보낼 안내문으로 정리해줘.
[원문]
```

파일 요청은 지정 파일을 직접 편집하고, 붙여 넣은 글은 수정본을 답한다. 내용 개선 의도가 명확하면 자동 선택할 수 있지만 의미 보존 교정 요청에는 자동 적용하지 않는다.

개발 중인 저장소의 스킬을 이 컴퓨터에서 연결 설치하려면 다음 명령을 사용한다.

```bash
bash scripts/install-codex-skill.sh korean-humanizer-deep
bash scripts/check-codex-skill.sh korean-humanizer-deep
```

기본 교정 스킬은 인수 없이 같은 명령을 실행한다. 기본 설치 경로는 `~/.agents/skills`이며 `CODEX_SKILLS_DIR`로 변경할 수 있다. 중복 표시를 막기 위해 기존 `$CODEX_HOME/skills`와 `~/.codex/skills`의 같은 이름 사본은 `~/.local/share/korean-humanizer/backups/`로 옮긴다. 백업은 삭제하지 않는다. 두 이름은 각각 한 항목으로 검색되어야 한다.

소스 저장소 자체가 검색 경로 안에 있으면 이동하지 않는다. 같은 물리 경로를 가리키는 연결은 Codex에서 한 스킬로 검색된다. 정리 대상 디렉터리 아래에 저장소가 중첩되어 있으면 저장소를 보존하고 오류로 종료하므로, 해당 경로를 먼저 분리한 뒤 다시 설치한다.

설치 전 시험하려면 `skills/korean-humanizer-deep/SKILL.md`의 절대 경로를 지정해 읽고 적용하도록 요청할 수 있다. 기존 Agensi JSON 생성기는 기본 교정 스킬용이며 deep을 포함하지 않는다. 공개 배포와 설치된 환경의 자동 선택 검증은 별도다.

## 기본 교정과의 선택 기준

| 요청 | 사용할 스킬 |
| --- | --- |
| AI 티만 제거, 번역체 수정, 의미와 말투를 유지한 표현 교정 | `korean-humanizer` |
| README 현행화, 코드·설정 대조, 프로젝트 관례에 맞춘 문서 개편 | `korean-humanizer-deep` |
| 붙여 넣은 초안을 독자·장르에 맞게 재구성 | `korean-humanizer-deep` |

deep은 파일을 받으면 관련 근거를 탐색하고, 붙여 넣은 글은 대화와 원문으로 시작한다. 다섯 가지 문체 패턴, 장르별 호흡과 설명 보존, 사실 변경의 근거 대조 표는 새 스킬의 실행 지침에서 관리한다.

## 검증 기준

고정 사례는 `eval/deep/evals.json`에 둔다. 실제 실행에서는 정답과 판정 항목을 전달하지 않고 입력 파일·요청·스킬 경로만 제공한다.

- 파일 편집: 작성 지침에 따른 말투 변경, 설정 근거로 오류 수정과 누락 보충, 비대상 파일 보존.
- 붙여 넣은 글: 대화의 독자·용도를 반영하고 사실·조건·약속의 강도 보존.
- 충돌 사례: 해소되지 않은 자료 충돌을 확정하지 않고 가능한 편집은 완료.
- 선택 경계: 표현만 교정·오탈자 수정·코드 수정 요청과 내용 개선 요청을 구분.

구조 검사는 실행 품질을 증명하지 않는다. 새 문맥의 실행은 해당 사례의 근거이며 일반 품질 성공률로 해석하지 않는다. 기본 에이전트와 같은 입력으로 비교하지 않았다면 효과 향상으로 보고하지 않는다. 자동 선택은 실제 설치 환경에서 별도로 확인해야 한다.

## 이름 변경 전 초안의 2026-10-30 실행 결과

`python3 eval/deep/run.py --output <새 결과 폴더>`로 고립된 작업 폴더와 새 Codex 문맥에서 후보 3건과 기본 에이전트 비교 1건을 실행했다. 같은 CLI 기본 설정과 권한을 사용했고 모델·추론 강도는 별도로 지정하지 않았다. 기본 에이전트도 설치된 다른 스킬을 사용할 수 있었으므로 무지침 모델과의 비교는 아니다.

| 사례 | 관찰 결과 |
|---|---|
| README 개선 | 해요체 적용, 실행 명령 수정, 실행 위치 보충, 재실행 조건·지원 예정 유지. README만 수정. `npm run preview` 실행 성공 |
| 메신저 본문 | 요청한 소제목·순서·해요체 반영. 발급 조건·최대 2영업일 가능성·담당자·URL 유지. 파일 생성 없음 |
| 자료 충돌 | 7일·30일 중 하나를 확정하지 않고 확인 필요 표시. 가능한 말투 개선 수행. setup.md만 수정 |
| 기본 에이전트 비교 | README의 같은 핵심 확인 항목 통과. 이 사례에서는 스킬의 추가 효과를 입증하지 못함 |

후보 결과 3건의 핵심 항목과 기준 비교 1건은 통과했다. 이는 문제 수정 전 실패를 확인한 회귀 검사가 아니라 새 기능의 사례별 실행 확인이다. 주관적 문장 품질의 독립·블라인드 평가는 하지 않았다. 선택 경계 3건은 평가 입력만 작성했으며 설치된 환경의 자동 선택은 실행하지 않았다.

이름 변경 전 초안은 구조 validator와 6사례 JSON 검사를 통과했다. 기존 카탈로그·교차 파일·예시 lint, 회귀 검사 15건, 패키징 검사 4건도 통과했다. 패키징 검사는 기존 스킬 생성기 검사이며 deep 배포 검증은 아니다.

추적 가능한 [출력·파일 해시·핵심 검사 결과](../../eval/deep/results/2026-10-30/checks.json)는 같은 결과 폴더에 보존했다. 원본 CLI 이벤트는 `/private/tmp/korean-humanizer-auto-eval-20261030/`에 있으며 임시 경로이므로 장기 보존을 보장하지 않는다.

## deep 보강과 로컬 설치 결과

`auto`를 `korean-humanizer-deep`으로 바꾸고 파일·붙여 넣은 글의 처리 분기, 다섯 가지 문체 점검, 장르별 호흡 보존, 사실 변경의 근거 대조 표를 추가했다. README와 선택 기준, 개발 설치기도 새 이름에 맞췄다. 과거 응답·기록 속 auto 이름은 당시 실행 근거로 보존한다.

기존 초안과 같은 입력으로 README·온보딩·블로그를 각각 비교했다. 독립 문장 평가에서 화자의 의도를 추측한 부분이 보여 지침을 보강하고 블로그를 다시 비교했다. 총 8회 실행이 정상 종료했다. README의 근거 대조 표는 이전 초안에 없고 deep에 있었다. 장르별 호흡과 대부분의 문체 항목은 이전 초안도 통과했으므로 일반적인 품질 향상으로 단정하지 않는다. 재실행 블로그에는 설정 범위 표현이 조금 느슨하고 일부 문장이 추상적이라는 평가가 남았다. [원본 응답·객관 검사·독립 평가와 한계](../../eval/deep/results/2026-10-30-deep/assessment.md)를 확인할 수 있다.

구조 validator, 평가 입력 7건의 JSON 검사, 카탈로그·교차 파일·예시 lint, 기존 회귀 검사 15건과 패키징 검사 4건이 통과했다. 설치 검사 2건은 변경 전 실패와 변경 후 통과를 확인했다. 중복 사본 백업, 재실행 시 유지, 사용자 지정 설치 루트와 deep 연결도 검사했다.

이 컴퓨터의 기존 Codex 사본 3개를 검색 경로 밖에 백업하고 기본 스킬과 deep을 저장소에 연결했다. Codex의 `skills/list`를 강제 재조회해 각 이름이 한 번씩 반환됨을 확인했다. deep은 Claude에도 설치했으며 원본·Codex·Claude의 런타임 파일 2개가 SHA-256 전체 목록 기준으로 일치한다. 기존 Claude 기본 스킬은 보존했다. 현재 열린 화면의 캐시 갱신은 직접 확인하지 않았으며 이전 목록이 남으면 새 대화에서 다시 확인한다. 공개 게시·푸시와 자동 선택 검증은 수행하지 않았다.

## PR 리뷰 보완

독립 코드 리뷰에서 소스 저장소가 기존 스킬 검색 경로 안에 있을 때 정리 루프가 저장소 자체를 백업으로 이동하는 회귀를 확인했다. 저장소 자체는 보존하고 같은 물리 경로의 별칭은 허용하도록 고쳤다. 정리 대상 아래에 저장소가 중첩된 경우에는 이동을 거부하고 실패를 보고한다. 추가한 회귀 검사 2건은 수정 전 커밋 `93349aa`에서 assertion 실패하고 수정 후 통과했다. 별도 임시 HOME의 실제 Codex `skills/list`에서도 공용 링크와 계정별 소스가 한 스킬로 검색됨을 확인했다.

Claude 자동 리뷰의 검증 공백 제안을 받아 `scripts/test-deep-skill.py`로 스킬 frontmatter·Codex 호출 메타데이터·평가 JSON과 fixture 경로를 검사하고 CI에 연결했다. 임시 복사본의 스킬 이름 불일치와 깨진 JSON을 각각 거부하는 것도 확인했다. 평가 응답 본문은 재교정하지 않고 파일 끝 개행만 추가해 Markdown 검사 경고를 정리했다.

첫 재리뷰에서는 기존 심볼릭 링크를 통해 설치기를 실행할 때 새 설치 링크도 그 옛 별칭을 가리키는 잔존 조건을 확인했다. 설치기·검사기의 저장소 경로를 `pwd -P`로 확정해 실제 소스를 가리키게 했다. 추가 검사 1건은 수정 전 `9200bd0`에서 exit 127로 실패하고 수정 후 통과했다.
