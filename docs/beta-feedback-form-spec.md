# 피드백 폼 spec — Google Form 작성 가이드

> 메인테이너가 Google Form 만들 때 그대로 복사해 쓸 질문 spec. 베타 사용자는 매 humanize 후 30 초 내 응답.

---

## 폼 메타

| 항목 | 값 |
|---|---|
| 제목 | `korean-humanizer 베타 피드백` |
| 설명 (form intro) | 1-2 문단 — 사용해주셔서 감사 / 평균 30 초 / 응답이 v1.0 룰 미세 조정에 직접 사용됨 |
| 응답 수집 | Email 수집 옵션 (선택). 익명 제출 가능. |
| 응답 제한 | 사용자당 다중 응답 OK (매 humanize 마다 1 회). |
| 진행 표시줄 | 활성 (사용자가 끝이 가까운지 알 수 있게). |
| 리디렉션 후 메시지 | "감사합니다. 다음 humanize 후 또 응답해주세요. 1-2 주 동안 5-10 회 응답이면 충분합니다." |

---

## 질문 7 개 + 선택 2 개

### Q1. 사용한 환경 (필수, 단일 선택)

라벨: `1. 어디서 humanize 했나요?`

옵션:
- Claude Code
- Claude.ai (Cowork)
- OpenCode
- Codex (OpenAI Codex CLI)
- ChatGPT
- Cursor
- Gemini
- 기타 (자유 응답으로 직접 답변)

### Q2. 도메인 (필수, 단일 선택)

라벨: `2. 어떤 글에 적용했나요?`

옵션:
- 블로그 / 브런치 / 워드프레스
- 마케팅 카피 / 광고 / 랜딩 페이지
- 격식 이메일 / 공문
- LinkedIn 포스트 / 코멘트
- YouTube 스크립트 / 인트로
- 뉴스레터 / 구독 메일
- 위키 / 백서 / 문서
- 학술 abstract / 논문 도입
- 뉴스 보도 / 기사
- 카카오톡 / DM / 메신저
- 제품 리뷰
- B2B 비즈니스 메시지 / 제안
- 기타 (자유 응답으로 직접 답변)

### Q3. 사용한 customization mode (필수, 단일 선택)

라벨: `3. 어떤 customization 으로 호출했나요?`

옵션:
- 기본 (12 카테고리만)
- Mode A — 인라인 한 줄 (`금지=...; 선호=A→B; 유지=...`)
- Mode B — 자연어 한 줄 ("X 빼고, Y 는 Z 로")
- Mode C — 파일 (`personal-list.md` 또는 `## My personal list`)
- Mode D — Brand voice profile (`brand-voice-*.md`)
- 여러 mode 동시 사용 (자유 응답으로 어떤 조합)

### Q4. 결과 만족도 (필수, 1-5 척도)

라벨: `4. 다듬어진 결과에 얼마나 만족하시나요?`

척도:
- 1 = 전혀 — 거의 매번 되돌리고 싶음
- 2 = 약간 부족
- 3 = 보통 — 절반은 만족, 절반은 미세 조정 필요
- 4 = 만족 — 그대로 사용 가능
- 5 = 매우 만족 — 내가 직접 다듬은 것보다 좋음

### Q5. 의미 보존 정도 (필수, 1-5 척도)

라벨: `5. 의미가 그대로 유지됐나요?`

척도:
- 1 = 의미 / 사실이 바뀐 부분이 1 곳 이상
- 2 = 미묘한 뉘앙스가 바뀜
- 3 = 표현이 약간 의역됨, 의미는 유지
- 4 = 의미 그대로
- 5 = 의미·뉘앙스·강조점 모두 그대로

> **1 점 응답이면 critical bug 신호.** Q8 자유 응답에 어느 부분이 바뀌었는지 적어주세요.

### Q6. 톤 일치 정도 (필수, 1-5 척도)

라벨: `6. 본인 (또는 의도한 brand) 톤과 얼마나 맞나요?`

척도:
- 1 = 완전히 다른 톤
- 2 = 비슷하지만 어색
- 3 = 보통 — 일부 어색
- 4 = 자연스러움
- 5 = 내가 쓴 듯

### Q7. 부족한 부분 (선택, 자유 응답, ~200 자)

라벨: `7. 부족하거나 어색했던 부분이 있다면? (구체적이면 도움 큼)`

힌트 (placeholder):
- "X 표현을 Y 로 바꿨는데 어색했음"
- "Z 도메인인데 ~다체로 바뀜 (발화체인데)"
- "humanizer 가 손대지 말았어야 할 단어를 손댐"
- "matter much 가 부족함 — 더 가볍게 / 더 강하게 다듬어줘 가 필요"

### Q8. 좋았던 부분 (선택, 자유 응답, ~200 자)

라벨: `8. 좋았거나 인상적이었던 부분이 있다면?`

힌트:
- "X 패턴 빼는 거 정확함"
- "내가 의식 못 했던 AI 티 잡아냄"
- "brand voice 가 톤 맞춰주는 게 만족스러움"

### Q9. 사용 텍스트 일부 공유 (선택, 자유 응답)

라벨: `9. (선택) raw / humanized 텍스트 일부를 익명화된 형태로 공개 사례 (README / examples) 에 포함하는 것에 동의하시나요?`

옵션:
- 동의 — 회사명 / 인물명 / 내부 도메인 마스킹 후 사용 OK
- 부분 동의 — 특정 텍스트만 (자유 응답에 명시)
- 비동의

### Q10. README contributor 표기 (선택, 자유 응답)

라벨: `10. (선택) v1.0 release 시 README contributor 섹션에 표기 원하시면 표기 이름 / GitHub username 적어주세요. (비공개 옵션이면 비워두세요.)`

자유 응답.

## 폼 설계 디테일

### 응답 시간 최적화

- Q1-Q3: 단일 선택 라디오. 5 초.
- Q4-Q6: 1-5 척도. 각 5 초.
- Q7-Q10: 선택 자유 응답. 0-60 초 (안 적어도 OK).

→ **평균 응답 시간 30-45 초** (자유 응답 안 적을 시).

### 응답 매번 안 적어도 됨 안내

폼 intro 에:

> "1-2 주 동안 5-10 회 응답이면 충분합니다. 매 humanize 마다 응답할 필요 없어요. **인상 깊은 케이스 (매우 만족 / 매우 불만족) 위주로** 응답해주시면 가장 도움 큽니다."

### 응답 분석 시점

- **매일**: 메인테이너가 새 응답 체크. critical bug 신호 (Q5 ≤ 2) 발견 시 24 시간 내 컨택.
- **Week 2 종료 시점**: 응답 raw 데이터 → `docs/beta-feedback.md` 익명화 정리.
- **Week 3 종료 시점**: 응답 분석 → 룰 미세 조정 PR.

### 데이터 보안

- 폼 응답 raw 데이터: Google Drive 비공개 폴더. 메인테이너 외 접근 금지.
- `docs/beta-feedback.md` 에 누적할 때:
  - 사용자 식별자 제거 (Q10 의 표기 동의자만 release notes 에 인용).
  - Q9 의 "동의" 응답자의 텍스트만 익명화 후 인용.
  - 회사명 / 인물명 / 내부 도메인 마스킹 (`[회사명]` / `[X 사람]` / `[domain]`).

## 폼 만들고 나서

1. Google Form 만든 후 **공유 가능 링크** 생성 (응답 권한: 누구나).
2. 링크를 다음 위치에 붙여넣기:
   - `docs/beta-guide.md` 의 "🔗 [피드백 폼 링크]" 자리
   - 베타 사용자에게 환영 메시지 (`docs/beta-recruit.md` 의 "Week 2 — 사용 시작" 체크리스트 참조)
3. **테스트 응답 1 회** — 본인이 응답해서 spreadsheet 자동 저장 확인.
4. 응답 spreadsheet 의 column 이 위 spec 과 매칭되는지 확인.

## v1.0 출시 후 폼 유지

- v1.0 release 후 **30 일** 까지 폼 유지 — 자연 사용자 응답도 받음.
- 30 일 후 폼 닫고 → 1.0.x patch / 1.1 minor 의 데이터 베이스로 사용.
- v1.x 트랙에서 **새로운 폼 (사용자 만족도 정량 측정)** 별도 트랙으로 검토 (out-of-scope of S4).
