# 1.x → 2.x 마이그레이션 준비

**상태: 미출시 초안.** 마지막 출시 버전은 v1.0.1입니다. 이번 PR은 아래 호환성 변경을 2.0 후보로 준비합니다. 2.0 태그·릴리스·지원 개시를 뜻하지 않습니다.

[1.x 호환성 약속](STABILITY-PROMISE.md)은 기존 출시본에 그대로 적용합니다. 출력 형식·표 헤더·개인 설정 진입점·정량 규칙은 고정 영역이므로 이 변경을 1.x 패치로 소개하지 않습니다.

## 달라지는 동작

| 항목 | 1.x 약속·기존 방식 | 2.0 후보 | 전환 방법 |
|---|---|---|---|
| 기본 출력 | `Humanized`·변경 설명 등 정해진 섹션 | 교정한 본문만 출력 | 섹션 이름을 파싱하는 코드를 수정하거나 요청에 원하는 형식을 명시 |
| 첫 응답 안내 | 첫 응답에 되돌리기·재수정 안내 문구 포함 | 안내 문구를 자동으로 덧붙이지 않음 | 온보딩이 필요하면 서비스 안내에서 제공 |
| 개인 설정 | 고정된 `examples/personal-list.md` 진입점 | `personal=파일경로`로 명시한 파일만 로드 | 기존 설정 파일을 보존하고 요청에 경로 지정 |
| 카탈로그 표 | `나쁨` / `자연스러움` | `검토할 표현` / `치환 후보` | 표 헤더를 읽는 도구·기여 양식 수정 |
| 수정 문장 한도 | 전체 문장의 20% | `max(1, floor(문장 수 × 0.20))` | 짧은 글도 최대 한 문장 수정할 수 있음을 반영 |
| 입력 확인 | 도메인·참고 글 확인을 먼저 대기 | 명확한 용도는 바로 처리, 참고 글은 선택 | 대화 흐름에 필수 질문 응답을 전제로 두지 않기 |

Brand voice·개인 금지어도 원문의 사실·조건·말투를 바꿀 수 없습니다. 충돌하는 치환은 건너뛰고, 이미 자연스러운 표현은 유지합니다.

## 평가 결과를 읽는 방법

- 길이 90% 미만은 축약 요청이 없는 사례에서 실패로 잡습니다.
- 보존어는 원문에 있었던 단어와 등장 횟수를 기준으로 검사합니다.
- 의도적 실패 사례는 지정한 지표가 실제로 실패해야 검사가 통과합니다.
- 기존 과교정 fixture의 허용 실패는 평가표에 `fail`로 남습니다. 정상 결과로 바꾸어 집계하지 않습니다.

평가 기준 보완으로 예전 평가표와 통과 수가 달라질 수 있습니다. [평가 안내](../eval/README.md)와 [QA 기록](reviews/2026-10-01-qa.md)을 함께 확인하세요. 고정 쌍 검사는 모델 출력 품질의 성공률이 아닙니다.

## 사용자가 전환할 때

1. 기존 동작을 유지하려면 설치 저장소에서 `git checkout v1.0.1`로 출시 태그를 고정합니다.
2. 후보 변경을 시험할 때는 [PR #5](https://github.com/dotoricode/korean-humanizer/pull/5)의 변경을 확인하고 별도 복사본을 사용합니다.
3. 사용하는 출력 파서·개인 설정·카탈로그 표 파서를 위 표에 맞춰 확인합니다.
4. 숫자·날짜·링크·인용·조건·존댓말이 유지되는지 자신의 실제 입력으로 비교합니다.
