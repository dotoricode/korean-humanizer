# v1.0.1 이후 변경 안내

**상태: 다음 릴리스 준비. 버전 번호 미정.** 마지막 정식 릴리스는 v1.0.1입니다. 아래는 기존 스킬의 교정 기준·설정·문서를 보완한 내용이며 메이저 버전업을 전제하지 않습니다.

기존 설치·설정과 다른 부분은 버전 번호와 별개로 확인해야 합니다. 현재 버전 구분 기준은 [개발 계획](../ROADMAP.md)에 있으며, 과거 1.x의 규칙은 해당 출시 태그와 [정책 기록](STABILITY-PROMISE.md)에 남아 있습니다.

현재 버전 정책은 과거 SemVer의 1.x 호환성 보장을 그대로 이어받지 않습니다. 메이저 번호가 같아도 아래 개인 설정·표 헤더·수정량·길이 기준은 달라질 수 있습니다. 기존 방식이 필요하면 v1.0.1을 고정하고, 새 버전은 별도 프로젝트에서 설정과 파서를 확인한 뒤 전환합니다. 이 호환성 차이는 새 릴리스 안내에도 명시합니다.

## 달라지는 동작

| 항목 | v1.0.1·기존 방식 | 현재 변경 | 전환 방법 |
|---|---|---|---|
| 기본 출력 | `Humanized`·`주요 변경 (최대 5개)` | 기존 main 형식 유지 | 변경 목록은 최대 5개, 전체 diff는 별도 요청 |
| 첫 응답 안내 | 되돌리기·재수정 안내 문구 | 기존 main 문구 유지 | 두 번째 응답부터 생략 |
| 개인 설정 | 고정된 `examples/personal-list.md` 진입점 | `personal=파일경로`로 명시한 파일만 로드 | 기존 설정 파일을 보존하고 요청에 경로 지정 |
| 카탈로그 표 | `나쁨` / `자연스러움` | `검토할 표현` / `치환 후보` | 표 헤더를 읽는 도구·기여 양식 수정 |
| 교정 범위 | 문장 20%·문단 3곳·짧은 글 1–2표현 | 고정 수정량 제한 없음 | 의미·정보·말투와 실제 자연스러움으로 검수 |
| 길이 기준 | 원문 길이 90% 이상 | 고정 비율보다 정보 보존 우선 | 길이 비율을 통과 조건으로 사용하지 않기 |
| 입력 확인 | 도메인·참고 글 확인을 먼저 대기 | 명확한 용도는 바로 처리, 참고 글은 선택 | 대화 흐름에 필수 질문 응답을 전제로 두지 않기 |

Brand voice·개인 금지어도 원문의 사실·조건·말투를 바꿀 수 없습니다. 충돌하는 치환은 건너뛰고, 이미 자연스러운 표현은 유지합니다.

## 평가 결과를 읽는 방법

- 기존 fixture의 M1/M2/M3는 과거 보수적 편집 계약의 회귀 검사로 유지합니다. 새로운 기본 교정의 품질·합격 기준으로 사용하지 않습니다.
- 보존어는 원문에 있었던 단어와 등장 횟수를 기준으로 검사합니다.
- 의도적 실패 사례는 지정한 지표가 실제로 실패해야 검사가 통과합니다.
- 기존 과교정 fixture의 허용 실패는 평가표에 `fail`로 남습니다. 정상 결과로 바꾸어 집계하지 않습니다.

평가 기준 보완으로 예전 평가표와 통과 수가 달라질 수 있습니다. [평가 안내](../eval/README.md)와 [QA 기록](reviews/2026-10-01-qa.md)을 함께 확인하세요. 고정 쌍 검사는 모델 출력 품질의 성공률이 아닙니다.

## 사용자가 전환할 때

1. 기존 동작을 유지하려면 설치 저장소에서 `git checkout v1.0.1`로 출시 태그를 고정합니다.
2. 변경을 시험할 때는 별도 프로젝트에 main을 설치합니다. [PR #5](https://github.com/dotoricode/korean-humanizer/pull/5)는 main에 머지되었습니다.
3. 사용하는 출력 파서·개인 설정·카탈로그 표 파서를 위 표에 맞춰 확인합니다.
4. 숫자·날짜·링크·인용·조건·존댓말이 유지되는지 자신의 실제 입력으로 비교합니다.
