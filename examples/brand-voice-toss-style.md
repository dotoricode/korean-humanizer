# Brand Voice — Toss 풍 핀테크 (가상)

> 가상 핀테크 스타트업 "acme-fintech" 의 brand voice 프로필. 짧고 직설, 친근 격식 최소화. **실제 토스의 가이드를 사용한 게 아니라**, 한국 핀테크에서 자주 쓰는 톤을 추상화한 가상 케이스.
>
> 같은 spec 으로 자기 회사 brand voice 를 채울 때 참조용.

---

## Tone guide

- 1 문장 8-15 자 권장. 강조는 단어가 아니라 **문장 길이**로.
- 격식 인사 ("안녕하세요", "감사합니다") 는 **시작 / 마무리 1 회** 외 금지.
- 사용자를 "고객님" / "여러분" 으로 부르지 않는다. 그냥 "당신" / 생략 / "쓰는 분".
- 모든 동사는 평이형으로. ("제공해 드리고 있습니다" → "드려요" / "있어요")
- 숫자는 한국식. ("3.5 %" 보다 "3.5 퍼센트" 보다 "3.5 %" 그대로 — 표시는 raw 보존)
- 부정 표현 직설. ("쉽지 않습니다" → "어려워요")
- 비교는 "더" / "덜" 만. "보다 ~한" / "한층 더" / "더더욱" 모두 금지.
- 이모지 어떤 자리든 0 개. (이모지 없는 친근함이 토스 풍의 핵심.)
- 외래어 차용 (UX / API / SDK / 온보딩 등) 그대로 — 무리한 한글 대체 금지.

## Raw → Humanized 사례 3 개

### 사례 1 — 블로그 포스트 인트로 (마케팅 톤)

**Raw (AI 생성, AI 티 ↑)**:

> 안녕하세요, 여러분! 오늘은 저희 acme-fintech가 새롭게 출시한 혁신적인 송금 서비스에 대해 알아보도록 하겠습니다. 이 솔루션은 사용자 경험을 극대화하기 위해 다양한 기능을 활용하여 보다 편리한 송금 경험을 제공해 드립니다. 함께 살펴봅시다!

**Humanized (brand voice 적용)**:

> acme-fintech의 새 송금 서비스예요. 사용자 경험을 덜 복잡하게 만들고, 여러 기능을 쉽게 쓸 수 있게 설계했어요. 더 편하게 송금할 수 있도록 준비했습니다.

**적용된 brand voice 룰**:
- `ban`: 혁신적인, 활용, 극대화, 솔루션, 보다 ~한 → 약화 / 치환
- `prefer`: 제공하다 → 드리다 / 문맥상 "쓸 수 있게"
- 톤 가이드: 1 문장 8-15 자, 격식 인사 1 회만, "여러분" / "고객님" 금지
- 카테고리 #5 개시 ("안녕하세요 ~ 알아보도록 하겠습니다") 는 짧게 축소
- 마무리 호응 ("함께 살펴봅시다") 은 정보가 없어 생략

**대시간**: 47 음절 → 43 음절. 압축률 0.91.

---

### 사례 2 — 앱 푸시 / 카피 (한 줄)

**Raw**:

> 더욱 편리해진 송금 시스템을 통해 보다 빠르고 효율적인 금융 활동을 경험해 보세요!

**Humanized**:

> 더 편리해진 송금 시스템으로 더 빠르고 효율적인 금융 활동을 경험해 보세요.

**적용 룰**:
- `ban`: 보다 ~한 → 더 ~한
- `preserve`: "빠르게" 가 핵심 — humanized 에 "빨라졌어요" 로 살림
- 톤 가이드: 격식 마무리 ("경험해 보세요!" 의 강제 호응) 약화 — "보내보세요"
- 카테고리 #1 강조어 ("더욱") 를 "더" 로 약화
- 이모지 / 느낌표 자동 부착 금지

**대시간**: 38 음절 → 36 음절. 압축률 0.95.

---

### 사례 3 — 이메일 (계좌 알림)

**Raw**:

> 안녕하세요, 고객님. 항상 acme-fintech를 이용해 주셔서 감사합니다. 고객님의 계좌에 입금이 완료되었음을 알려드리며, 자세한 내역은 다음과 같이 확인 가능합니다. 추가 문의 사항이 있으시면 언제든지 고객 센터로 연락 주시기 바랍니다.

**Humanized**:

> 안녕하세요. acme-fintech를 써주셔서 감사합니다. 계좌에 입금이 완료됐어요. 자세한 내역은 앱에서 볼 수 있습니다. 궁금한 점이 있으면 고객 센터로 연락 주세요.

**적용 룰**:
- `ban`: 이용 → 쓰기
- `prefer`: 확인하다 → 보다 ("확인 가능합니다" → "봐요")
- 톤 가이드: "고객님" 금지, 격식 인사·마무리는 역할이 있어 보존하되 짧게 정리
- 카테고리 #5 개시·마무리는 통째 삭제하지 않고 짧게 조정
- 카테고리 #6 수동태 ("완료되었음을 알려드리며") → 능동 ("들어왔어요")
- 카테고리 #11 hedging ("연락 주시기 바랍니다") → 직설 ("연락 주세요")

**대시간**: 87 음절 → 82 음절. 압축률 0.94.

## 도메인 디폴트 ↔ 카탈로그 부록 E 매핑

이 brand voice 의 `domain_default: marketing` 일 때 부록 E 가 알려주는 우선 카테고리:

| 순위 | 카테고리 | 이 brand voice 가 강하게 작동하는 이유 |
|---|---|---|
| 1 | #2 공허한 형용사 | "혁신적인" 등 ban 직접 매칭 |
| 2 | #12 고빈도 어휘 | "활용" / "극대화" / "솔루션" 모두 ban |
| 3 | #1 강조어 | "보다 ~한" / "더더욱" ban |

도메인이 `email` 로 바뀌면 부록 E 의 1 순위가 #11 hedging 이 되며, 이 brand voice 의 `~해요` ending 이 raw 의 `~합니다` 격식과 충돌할 수 있다 → **brand voice 의 ending_default 가 raw 도메인 디폴트보다 우선** (사례 3 처럼 이메일도 `~해요` 로 통일).

## 한계 / 주의

- 이 brand voice 는 문장을 짧게 만들지만, 일반 humanize 와 마찬가지로 정보량을 보존한다.
  - `length_bias: concise` 는 문장 길이와 어휘 밀도를 낮추라는 뜻이지, 주장 / 근거 / CTA 를 빼라는 뜻이 아니다.
  - 사용자가 "짧게"를 요청하지 않았다면 원문 대비 90% 미만으로 줄이지 않는다.
- "쉽게 / 빠르게 / 간편하게" 가 raw 에 있으면 **반드시 보존**. 이 단어가 곧 핀테크 톤이라서.
- 이모지 0 개 룰이 디자인 시스템 (앱 카피의 아이콘 / 일러스트레이션) 까지 막지는 않는다. **텍스트 안의 이모지** 만 금지.
