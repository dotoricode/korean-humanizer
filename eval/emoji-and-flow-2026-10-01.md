# 이모지 역할·문장 흐름 보완 검증

상투적인 장식은 제거하고 감정·농담·상태 구분·명시적인 유지 요청은 보존하도록 지침을 바꿨습니다. 인접 문장의 같은 사건·요청·이유는 한 번만 전달하도록 마지막 검토를 보완했습니다.

## 이메일이 어색했던 이유

이전 실제 출력은 “일정을 변경해야 해서 연락드립니다” 뒤에 “일정을 바꾸게 되어 양해 부탁드립니다”를 이어 같은 사건을 반복했습니다. 두 문장을 각각 치환한 결과로 해석할 수 있으며 모델 내부 판단을 확인한 것은 아닙니다. 기존 지침은 동사 결합의 중복만 언급했습니다. 이번에는 글 전체에서 사건의 반복을 확인하고 연락 목적·불가피한 사유·양해 요청을 모두 남기도록 정했습니다.

## 실행 조건

- 날짜: 2026-10-01, 최종 지침의 입력 8개·두 모델·각각 새 대화 1회
- 소스: `52b26ffa4aef966731e04fbbe22ac200bd532c46`, SKILL·카탈로그 SHA-256은 JSON에 기록
- Claude Code 2.1.286: `claude-opus-5-5`, medium; 응답 modelUsage에서도 같은 ID 확인
- Codex CLI 0.159.3: `gpt-6-astra`, medium; 서버의 별도 모델 식별자는 반환되지 않음
- 지침·카탈로그 전체를 동일 요청에 직접 전달; 도구 비활성화 또는 사용 금지; 수동 답안 미전달
- 실제 응답 전체와 요청 해시: [JSON 기록](model-runs/emoji-and-flow-2026-10-01.json)

## 독립 검토

모델명을 숨긴 원문·도메인·사용자 요청·실제 본문 16개를 독립 검토자가 읽었습니다. 의미·조건·확신·말투 보존과 이모지 계약의 실제 위반은 발견하지 못했습니다. 이메일에서 같은 일정 변경을 반복하던 문제도 사라졌습니다.

Opus의 “일정을 변경하게 되어”는 변경 필요보다 결정된 상황처럼 읽힐 여지가 있어 “변경해야 해서”가 더 직접적이라는 개선 의견은 남았습니다. 검토자 1명의 작은 검사이며 출력은 수동으로 고치지 않았습니다. 앞선 후보에서 신규성을 보태던 출력과 재검토 경위는 JSON의 `diagnostics`에 보존했습니다.

## 재현과 한계

JSON의 소스 커밋에서 SKILL·카탈로그를 읽어 `request_template`에 넣습니다. `keep` 사례만 요청에 “🚀는 그대로 남겨줘”를 추가합니다. [앞선 실행의 CLI 옵션](model-comparison.md#재현)을 동일하게 사용했습니다.

이는 지침 직접 전달 검사이며 자동 스킬 발견·설치 경로 검증이 아닙니다. 두 CLI의 기본 지침과 medium 처리량은 다를 수 있습니다. 입력당 1회 결과이며 품질 성공률·모델 우열·항상 같은 출력은 보장하지 않습니다. 고정 fixture 25개는 과거 계약의 회귀 검사로 별도 관리합니다.
