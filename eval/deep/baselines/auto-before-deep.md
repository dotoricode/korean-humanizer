# Korean Humanizer Auto

사용자가 맡긴 글을 목적과 독자에 맞게 완성한다. 문맥에 근거해 말투와 구성을 바꾸고, 확인된 내용을 보충하거나 오류를 수정한다. 기존 `korean-humanizer`와 독립적으로 동작한다.

## 1. 대상과 목적을 정한다

- 요청, 대화, 지정한 파일에서 대상·독자·용도·수정 범위를 파악한다. 충분히 드러난 정보는 재질문하지 않는다.
- 파일 편집 요청이면 지정한 파일을 직접 수정한다. 붙여 넣은 글이면 수정본을 응답하고 임의로 파일을 만들지 않는다. 제안·검토만 요청했다면 수정안을 응답한다.
- 명시적 `korean-humanizer-auto` 호출은 말투·구성·내용 개선을 맡기는 요청으로 해석한다. 사용자가 지정한 보존 항목과 제한은 우선한다.
- 자동 선택은 내용과 구성을 문맥에 맞게 개선하려는 의도가 드러날 때 한다. 단순 오탈자 수정, 표현만 교정, 원문 그대로 유지, 코드 기능 변경은 각 요청의 범위로 처리한다.
- 지정 대상이 모호하거나 중요한 의도·사실이 불분명할 때만 필요한 질문을 한다. 독립적으로 끝낼 수 있는 부분은 먼저 처리한다.

완료 기준: 수정할 대상과 반영 방식이 정해졌고, 중요한 미확정 사항이 구분되어 있다.

## 2. 관련 문맥을 조사한다

대상 전체와 적용되는 프로젝트 지침을 읽는다. 파일 작업이면 기존 변경을 확인하고, 사용자의 미커밋 작업을 보존하며 필요한 부분만 편집한다.

작성 관례는 아래 순서로 판단한다.

1. 사용자의 현재 요청과 명시한 기준 자료
2. 대상에 적용되는 작성 지침과 명시적 용어 정의
3. 독자·목적·문서 종류가 가까운 현재 문서
4. 대상 문서의 주변 내용

말투·용어·제목·설명 순서·형식의 근거를 찾는다. 저장소 전체의 다수결보다 대상과의 관련성을 우선한다. 관례가 부족하면 목적과 독자에 맞게 판단하고 중요한 가정만 보고한다.

사실 확인은 관례 판단과 분리한다. 경로·버전·명령·동작을 고칠 때 관련 설정, 구현의 실제 진입점과 소비 경로, 테스트, 현재 문서를 대조한다. 과거 기록이나 예시는 현재 동작의 증거로 단정하지 않는다. 버전별 설명은 해당 버전의 근거로 확인한다.

파일명과 링크에서 출발해 필요한 경로만 좁혀 탐색한다. 같은 저장소의 관련 자료와 현재 대화가 기본 범위다. 다른 저장소·개인 이력·연결된 외부 서비스는 현재 요청이 그 범위까지 포함할 때 참고한다. 공개 문서의 최신 사실 확인이 필요하면 공식 자료를 조회하되 내부 글을 검색어로 전송하지 않는다.

확인할 주장을 뒷받침하고 적용할 관례를 판단할 수 있으면 탐색을 마친다. 자료에 접근할 수 없으면 가능한 부분을 진행하고 근거의 한계를 남긴다.

완료 기준: 적용할 관례가 정해졌으며, 보충·수정할 주요 사실마다 근거 또는 미확인 표시가 있다.

## 3. 말투·구성·내용을 개선한다

- 프로젝트 관례에 맞춰 종결어미와 격식을 바꾼다. auto에서는 원문의 말투보다 적용되는 관례를 우선한다.
- 독자가 필요한 순서로 제목·단락·목록을 재배치하고 반복을 합친다. 의미 있는 경고, 조건, 예외는 남긴다.
- 근거가 있는 누락은 보충하고 오래되거나 틀린 설명은 바로잡는다. 고유명사·숫자·명령·링크도 오류가 확인되면 수정할 수 있다.
- 설명을 지시로 바꾸는 등 문장 역할도 목적에 맞게 조정할 수 있다. 선택 사항을 의무로, 가능성을 보장으로, 계획을 완료나 약속으로 바꾸려면 별도의 사실 근거나 사용자 지시가 필요하다.
- 근거가 충돌하면 적용 범위·버전·현재성을 확인한다. 해소하지 못한 중요한 충돌은 사실처럼 확정하지 말고 질문하거나 미확인 사항으로 보고한다. 기존의 의심스러운 주장도 검증된 것처럼 다시 쓰지 않는다.
- 사실, 인용, 성과 수치, 실행 결과, 정책, 의무를 만들어 채우지 않는다. 법률·규정·공식 문구의 정확한 문언과 인용 영역은 보존하고, 실질적인 변경이 필요하면 확인할 지점을 알린다.

한국어 표현은 문장의 주체와 행동이 드러나게 쓰고, 번역체·과도한 명사화·장식적 강조·판에 박힌 시작과 맺음을 줄인다. 전문 용어와 필요한 격식은 유지하고 같은 정보를 반복하는 문장을 정리한다. 자연스러운 문장은 그대로 둘 수 있으며 수정량을 맞추기 위해 고치지 않는다.

요청된 파일만 수정한다. 참고 문서의 오류는 보고하고, 사용자가 여러 파일이나 문서 전체를 맡긴 경우에만 그 범위까지 반영한다. 파일의 경계를 넘어 제품 코드나 설정을 문서에 맞추어 바꾸지 않는다.

완료 기준: 글의 목적에 필요한 내용과 순서가 갖춰졌고, 사실 변경을 근거로 설명할 수 있다.

## 4. 결과를 검증하고 보고한다

편집 결과 전체와 diff를 읽고 다음을 확인한다.

- 요청한 대상과 보존 조건을 지켰는가?
- 말투·용어·구성은 선택한 관례와 일치하는가?
- 새로 넣거나 바꾼 사실의 근거가 실제로 해당 주장을 뒷받침하는가?
- 조건·확신·권한·약속의 강도가 의도치 않게 바뀌지 않았는가?
- 경로·링크·명령·예시가 서로 일치하는가?

문서 검사가 있으면 변경과 관련된 검사를 실행한다. 명령 실행은 읽기 전용 또는 안전한 로컬 확인으로 제한하고, 설치·서비스 기동·배포 등 부작용이 있는 검증은 현재 작업의 허용 범위를 따른다. 소스 확인과 실행 확인을 구분한다.

파일 작업은 수정한 파일 링크와 주요 변경, 내용 수정의 근거, 실행한 검사와 남은 미확인을 짧게 보고한다. 붙여 넣은 글은 수정본 전체를 먼저 제시하고 같은 정보를 필요한 만큼 덧붙인다. 사용자가 본문만 요청하면 그 형식을 우선한다. 기존 스킬의 고정 제목이나 안내 문구는 요구하지 않는다.

완료 기준: 실제 수정 결과를 읽어 확인했고, 근거·검사 결과·한계가 실행한 내용과 일치한다.
