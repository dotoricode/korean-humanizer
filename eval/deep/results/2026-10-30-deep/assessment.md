# deep 보강 비교 평가

공개 기록의 개인 홈·체크아웃 경로는 자리표시자로 정규화했다. 원본은 로컬에 보존했다.

## 실행과 객관 검사

기존 auto 초안과 deep을 같은 입력·권한·CLI 기본 설정으로 새 문맥에서 비교했다. 모델과 추론 강도는 지정하지 않았다. README·온보딩·블로그 각 2회, 서사 보강 뒤 블로그 각 2회로 총 8회 모두 정상 종료했다. 원본 이벤트는 `/private/tmp/korean-humanizer-deep-eval-20261030-retry/`와 `/private/tmp/korean-humanizer-deep-eval-20261030-blog-recheck/`에 있다. 임시 경로의 장기 보존은 보장하지 않는다. 이 폴더에는 원본 응답, 변경 README, 요청, 해시·실행 기록과 추출한 명령·사용량을 보존했다.

[객관 검사](checks.json)에서 README만 변경되고 실행 명령·조건·지원 예정 상태가 보존됐다. 양쪽 모두 실제 `npm run preview`가 성공했다. 근거 대조 표는 기존 초안에서 없었고 deep에서 변경 전후와 설정·구현을 연결했다. 붙여 넣은 두 글은 파일 변경과 저장소 탐색 없이 처리했다. 스킬·작성 지침과 인접한 메신저 스킬은 읽을 수 있었으므로 무지침 모델과의 비교가 아니다.

## 블라인드 문장 평가

별도 평가자에게 원문과 A/B 결과만 주고 스킬 구현·개선 의도를 전달하지 않았다. 온보딩은 양쪽 모두 조건과 배려 어조를 보존했고, deep의 접속 안내가 반복을 덜었다. 블로그는 양쪽 모두 시행착오를 보존했으며 뚜렷한 우열은 없었다. README의 `사용자 추가 메모:` 표현은 독자용 문서에서 어색하다는 의견이 있었다. 근거 표는 확인에 도움이 되지만 짧은 보고에는 무겁다는 의견도 있었다.

최초 블로그 결과에서는 양쪽 모두 원문에 명시되지 않은 의도나 계획을 조금 보탰다. deep에 화자 동기·의도도 근거 범위에서만 쓰도록 보강하고 같은 사례를 다시 실행했다. 별도 평가자는 재실행된 deep에서 이전 생각·계획 확장이 해소됐다고 판단했다. 다만 설정을 모은 범위가 조금 덜 정확해졌고, ‘설정 변경 경로를 제어’라는 표현이 추상적이라는 한계가 남았다.

평가 입력을 묶을 때 파일 경로를 basename으로 표시한 실수가 있었다. 실제 `docs/usage.md`를 `usage.md`로 제시해 평가자가 처음에 링크 불일치를 지적했으며, 원래 경로를 확인한 뒤 해당 지적을 철회했다. 실행·변경 파일 범위는 블라인드 평가가 아니라 실제 명령 이벤트와 파일 해시로 확인했다.

## 해석과 미실행

근거 표의 추가는 기존 초안과 차이를 확인했다. 문체 패턴 제거와 장르별 호흡은 기존 초안도 대부분 통과했으므로 일반 품질 향상이나 성공률로 해석하지 않는다. 독립 평가도 세 사례에 한정된다. 최종 동기 보존 문장 추가 후에는 영향을 받는 블로그만 재실행했고, README·온보딩은 직전 실행 근거를 재사용했다. 충돌 사례는 이전 실행 기록을 보존했으며 이번에 다시 실행하지 않았다. 자동 라우팅 경계는 입력 3건만 작성했고 실제 자동 선택은 측정하지 않았다.
